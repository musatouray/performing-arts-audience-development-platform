# Governance standards (v1)

*This is the document I'd publish in month one, so the team repeats good decisions without me in the room.*

## 1. Ownership (RACI)

| Asset | Accountable | Responsible | Consulted | Informed |
|---|---|---|---|---|
| Platform (tenant settings, capacity, topology) | BI Data Architect | BI Data Architect | CIO, Director of BI | BI team |
| Source extracts and ingestion | BI Data Architect | Data engineers | Source system owners (`owner` in `sources.yaml`) | Analysts |
| DQ rules for an entity | Business data owner | Data engineers | Analysts | Director of BI |
| Certified semantic model | Director of BI | BI developer | Business owner | All consumers |
| Access requests | Business data owner (approves) | Fabric admin (adds to group) | n/a | Requester |

## 2. Certification criteria (Promoted › Certified)

A semantic model is **Certified** only when all of these are true:

1. It's built on **Gold** only, with no direct Silver or Bronze sources.
2. Measures match `rpt.*` view definitions. A reconciliation query is attached to the PR.
3. RLS/OLS roles are defined, mapped to groups, and tested with "Test as role", with screenshots in the PR.
4. Descriptions are filled in for every visible table, column and measure. Display folders are used.
5. It carries a sensitivity label and has a named owner.
6. It has been deployed through the pipeline (DEV › TEST › PROD), with UAT sign-off in TEST by the business owner.
7. It passes Best Practice Analyzer (Tabular Editor / semantic-link-labs) with no errors.

## 3. Data quality SLA

| Metric | Target | Where it's measured |
|---|---|---|
| Daily load complete by | 07:00 ET | `rpt.vw_pipeline_health` |
| Bronze reconciliation | 100% `OK` | `lh_bronze.audit.reconciliation` |
| Error-rule pass rate per entity | ≥ 99.5% | `rpt.vw_dq_latest` |
| Unknown-member facts | < 0.5% of rows | `rpt.vw_gold_integrity` |
| Quarantine triage | Within 2 business days, by the data owner | `lh_silver.dq.quarantine` |

## 4. Access model

- Access is **always** granted by adding a person to an `sg-hh-*` group. Nobody is granted access directly.
- Consumers get **Apps**, not workspace roles.
- PROD workspaces: builders are Viewers, and changes go through deployment pipelines only.
- Contact PII (email, phone, address) is visible to the Development group only:
  - lake: OneLake column security
  - SQL: DDM + UNMASK
  - reports: OLS
- Anonymous gifts are visible only to `sec.privileged_users` and the Development role.
- **Never** land payment card data in OneLake (PCI scope). Ticketing extracts exclude card fields at source.
- Education data stays aggregate. No student-level records are ingested.

## 5. Change management

- All changes go through a PR. CI runs lint, config validation, tests and the notebook build. CODEOWNERS reviews security files.
- Tenant-setting changes are recorded in `docs/tenant-settings-audit.md` (regenerated by `scripts/08`) and committed.
- Every ADR ends with a **"revisit when"** trigger, reviewed quarterly.

## 6. Self-service enablement

- **Office hours:** weekly, 30 minutes, open to everyone.
- **Certified model catalog:** the OneLake catalog filtered by the Certified endorsement.
- **Build permission** on certified models lets analysts create their own reports without touching the data.
- **"Report on a certified model" training:** four sessions per year for business users.
